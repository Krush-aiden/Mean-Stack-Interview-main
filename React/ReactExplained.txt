R19-1. Form Actions & useActionState()
React 19 lets you pass an async function directly to a <form action={...}> attribute.
useActionState(action, initialState) wraps that action and returns [state, formAction, isPending].
- state     : the last returned value from your action function.
- formAction: the function you pass to <form action={}>.
- isPending : true while the action is running — replaces a separate loading useState.

Before React 19 (multiple state hooks):
  const [loading, setLoading] = useState(false);
  const [error,   setError]   = useState(null);
  const [data,    setData]    = useState(null);

With React 19:
  async function submitAction(prevState, formData) {
    const name = formData.get('name');
    const res  = await saveToAPI(name);
    if (!res.ok) return { error: 'Failed to save' };
    return { success: true };
  }

  const [state, formAction, isPending] = useActionState(submitAction, null);

  return (
    <form action={formAction}>
      <input name="name" />
      <button disabled={isPending}>{isPending ? 'Saving...' : 'Save'}</button>
      {state?.error && <p>{state.error}</p>}
    </form>
  );

Key point: cleaner form handling — no manual loading/error state juggling.

R19-2. useFormStatus Hook
useFormStatus() gives any child component inside a <form> access to the parent form's
submission state (pending, data, method, action) — without prop drilling or Context.

import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending } = useFormStatus();
  return <button disabled={pending}>{pending ? 'Submitting...' : 'Submit'}</button>;
}

// Works regardless of nesting depth inside the form:
<form action={formAction}>
  <input name="email" />
  <SubmitButton />
</form>

Key point: ideal for reusable submit buttons and deeply nested form children.

R19-3. useOptimistic Hook
useOptimistic(state, updateFn) shows an immediate UI update while an async operation
runs in the background. React automatically rolls back if the operation fails.

import { useOptimistic } from 'react';

function ChatApp({ messages, sendMessage }) {
  const [optimisticMsgs, addOptimistic] = useOptimistic(
    messages,
    (current, newMsg) => [...current, { text: newMsg, pending: true }]
  );

  async function handleSend(formData) {
    const text = formData.get('message');
    addOptimistic(text);       // instant UI update (greyed out)
    await sendMessage(text);   // actual async API call
  }

  return (
    <>
      {optimisticMsgs.map((m, i) => (
        <p key={i} style={{ opacity: m.pending ? 0.5 : 1 }}>{m.text}</p>
      ))}
      <form action={handleSend}>
        <input name="message" /><button>Send</button>
      </form>
    </>
  );
}

Key point: best for chat messages, todo items, likes/reactions — instant perceived performance.

R19-4. The use() API
use(promise | context) reads a Promise or Context value directly in the component body.
Unlike hooks, it CAN be used inside conditionals and loops.

// Reading context:
import { use } from 'react';
const theme = use(ThemeContext);

// Reading a promise (suspends until resolved — needs Suspense boundary):
function UserProfile({ userPromise }) {
  const user = use(userPromise);
  return <p>{user.name}</p>;
}

Limitations:
- Must be wrapped in a <Suspense> boundary.
- Without a caching layer (React cache(), Next.js, TanStack Query), the promise
  is re-created on every render — causing infinite refetching.
- Cannot be called in event handlers or plain functions.

Key point: simplifies async data reading but requires a proper caching strategy.

R19-5. Passing Refs as Props (forwardRef no longer needed)
Before React 19, passing a ref to a child component required forwardRef():

  // Old:
  const Input = forwardRef((props, ref) => <input ref={ref} {...props} />);

React 19: ref is now a regular prop — no wrapping required:

  function Input({ ref, ...props }) {
    return <input ref={ref} {...props} />;
  }

  // Usage:
  const inputRef = useRef();
  <Input ref={inputRef} placeholder="Search" />;

Key point: cleaner component code, forwardRef is deprecated and no longer needed.

12. How Hydration Works
**Hydration** in React refers to the process of attaching event listeners and making a server-rendered HTML page interactive. When a React application is server-side rendered (SSR), the HTML is generated on the server and sent to the client. The client then "hydrates" this HTML by attaching the necessary event listeners and making it interactive using the React JavaScript code.


1. **Server-Side Rendering (SSR)**:
   - The server generates the HTML for the initial page load.
   - This HTML is sent to the client and displayed in the browser.

2. **Hydration**:
   - The React JavaScript code is loaded on the client.
   - React attaches event listeners to the existing HTML elements.
   - The application becomes interactive without re-rendering the entire HTML.

### Example

**Server-Side Rendered HTML**:
```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>React App</title>
</head>
<body>
  <div id="root">
    <h1>Hello, World!</h1>
    <button>Click me</button>
  </div>
  <script src="/static/js/bundle.js"></script>
</body>
</html>
```

**Client-Side Hydration**:
```javascript
import React from 'react';
import ReactDOM from 'react-dom';
import App from './App';

// Hydrate the existing HTML with React
ReactDOM.hydrate(<App />, document.getElementById('root'));
```

**App Component**:
```javascript
import React from 'react';

function App() {
  const handleClick = () => {
    alert('Button clicked!');
  };

  return (
    <div>
      <h1>Hello, World!</h1>
      <button onClick={handleClick}>Click me</button>
    </div>
  );
}

export default App;
```

### Benefits of Hydration

- **Improved Performance**: Hydration allows the initial HTML to be displayed quickly, improving the perceived performance of the application.
- **SEO Benefits**: Server-side rendering provides fully rendered HTML to search engines, improving SEO.
- **Faster Time-to-Interactive**: Hydration makes the application interactive faster by attaching event listeners to the existing HTML.

### Conclusion

Hydration is a crucial process in React applications that use server-side rendering. It allows the server-rendered HTML to become interactive on the client side without re-rendering the entire page, providing a seamless user experience and improving performance.

21. What is reconciliation in React?
Reconciliation is the process React uses to update the DOM efficiently. When the state or props of a component change, React compares the new Virtual DOM with the previous one (using a diffing algorithm) and updates only the parts of the real DOM that have changed.

Key Points:
React uses the Virtual DOM to track changes.
The diffing algorithm identifies the minimal set of changes required to update the real DOM.
This process ensures better performance by avoiding unnecessary DOM manipulations.


22. How does React’s diffing algorithm work?
React’s diffing algorithm is used to efficiently compare the new Virtual DOM with the previous one and determine the minimal changes required to update the real DOM.

How it works:
Element Type Comparison:
If the element types are different, React destroys the old element and creates a new one.
Key Prop:
React uses the key prop to identify elements in a list and track their positions.
Tree Comparison:
React compares elements at the same level in the tree.
It does not compare elements across different levels.

49. What are the different types of exports and imports?
In JavaScript (and React), there are two types of exports and imports:

Default Export and Import:
Used to export a single value from a module.
Import does not require curly braces.
Example:
```
// File: math.js
export default function add(a, b) {
  return a + b;
}

// File: app.js
import add from './math';
console.log(add(2, 3)); // Output: 5
```

Named Export and Import:
Used to export multiple values from a module.
Import requires curly braces.
Example:
```
// File: math.js
export const add = (a, b) => a + b;
export const subtract = (a, b) => a - b;
```

50. What are the differences between createElement vs cloneElement in React?
React.createElement:
- Creates a new React element.
- Used to create elements programmatically.
```
const element = React.createElement('div', { className: 'container' }, 'Hello, World!');
```
React.cloneElement:
- Clones an existing React element and optionally modifies its props or children.
- Used to reuse or modify existing elements.
```
const element = <div className="container">Hello</div>;
const clonedElement = React.cloneElement(element, { className: 'new-container' });
```

51. When to use useState and useReducer?
useState:
- Used for simple state management.	
- const [state, setState] = useState(initialState);	
- Simple counters, toggles, or form inputs.
```
const [count, setCount] = useState(0);
```

useReducer:
- Used for complex state logic or when state depends on previous state.
- const [state, dispatch] = useReducer(reducer, initialState);
- Complex state transitions, such as managing a form with multiple fields.
```
const reducer = (state, action) => {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 };
    case 'decrement':
      return { count: state.count - 1 };
    default:
      return state;
  }
};

const [state, dispatch] = useReducer(reducer, { count: 0 });
```

55. What is super in the constructor in Class-based Components?
In class-based components, super is used to call the constructor of the parent class (React.Component). It is required when you want to access this.props or this.state in the constructor.
ex:
```
class MyComponent extends React.Component {
  constructor(props) {
    super(props); // Calls the parent class constructor
    this.state = { count: 0 };
  }

  render() {
    return <h1>Count: {this.state.count}</h1>;
  }
}
```

Key Points:
super(props) must be called before accessing this in the constructor.
It ensures that the parent class (React.Component) is properly initialized.
