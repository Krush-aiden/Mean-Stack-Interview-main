## PART 3: BACKEND NODE.js MINI PROJECTS

> These are standalone, small projects (2-5 hrs each) to practice backend concepts.  
> Like your React mini-projects — each focuses on one concept.  
> Build each inside a folder like `backend-mini-projects/01-rest-crud/`

---

### Core Backend Projects (Build These First)

#### 1. REST API CRUD — Blog/Notes App

**Concepts:** Express setup, CRUD routes, MongoDB/Mongoose, proper status codes, error handling middleware

```
Features:
- POST /api/notes — create a note (title, content, tags)
- GET /api/notes — list all (with pagination, sorting, filtering)
- GET /api/notes/:id — get single note
- PUT /api/notes/:id — update
- DELETE /api/notes/:id — soft delete
- Centralized error handler middleware
- Request validation with Joi/Zod
```

---

#### 2. Auth System (JWT + Refresh Tokens)

**Concepts:** Registration, login, JWT access+refresh tokens, password hashing, protected routes

```
Features:
- POST /api/auth/register — bcrypt password, save user
- POST /api/auth/login — return access token (15min) + refresh token (7d)
- POST /api/auth/refresh — rotate refresh token
- POST /api/auth/logout — invalidate refresh token
- GET /api/auth/me — protected route (auth middleware)
- Role-based middleware (admin vs user)
- HttpOnly cookie for refresh token
```

---

#### 3. File Upload Service

**Concepts:** Multer, file validation, image processing with Sharp, cloud storage

```
Features:
- POST /api/upload — upload image (multer)
- Validate file type (only jpg/png/webp) and size (<5MB)
- Auto-generate thumbnail (Sharp — resize to 200x200)
- Store in /uploads/ or Cloudinary
- GET /api/files/:id — serve/redirect to file
- DELETE /api/files/:id — remove file + DB record
```

---

#### 4. URL Shortener

**Concepts:** Hashing, base62 encoding, redirect, rate limiting, analytics

```
Features:
- POST /api/shorten — accept long URL, return short code
- GET /:code — redirect to original URL (301)
- GET /api/stats/:code — click count, last accessed, referrer
- Rate limiting (max 10 URLs/hour per IP)
- Auto-expire old URLs (TTL index on MongoDB)
- Collision handling for short codes
```

---

#### 5. Real-time Chat (WebSocket)

**Concepts:** Socket.io, rooms, namespaces, event-driven architecture

```
Features:
- Socket.io connection with JWT auth
- Join/leave rooms
- Broadcast messages to room
- Typing indicator
- Online user list
- Message history from MongoDB
- Acknowledgement (message delivered/read)
```

### Intermediate Projects (After Core)

#### 6. Job Queue & Background Tasks

**Concepts:** BullMQ, Redis, worker processes, retry logic

```
Features:
- POST /api/email — queue an email job (don't send in request)
- Worker process picks up jobs from queue
- Retry failed jobs (3 attempts with exponential backoff)
- GET /api/jobs/:id — check job status
- Dashboard route showing queue stats
- Priority levels (urgent emails first)
```

---

#### 7. Rate Limiter Service

**Concepts:** Sliding window, token bucket, Redis, middleware

```
Features:
- Middleware: rate limit by IP (100 req/min)
- Middleware: rate limit by user (authenticated — 500 req/min)
- Sliding window algorithm using Redis sorted sets
- Token bucket algorithm alternative
- Custom rate limit per route (/api/auth — 5 req/min)
- Return proper 429 headers (Retry-After, X-RateLimit-Remaining)
```

---

#### 8. Webhook Receiver & Sender

**Concepts:** HMAC signature verification, retry logic, idempotency

```
Features:
- POST /api/webhooks/register — register a webhook URL
- Dispatch events to registered URLs (with HMAC signature)
- POST /api/webhooks/receive — receive & verify webhook
  - Verify HMAC-SHA256 signature
  - Idempotency key to prevent duplicate processing
- Retry failed deliveries (3 attempts, exponential backoff)
- GET /api/webhooks/logs — delivery history
```

---

#### 9. Caching Layer with Redis

**Concepts:** Cache-aside pattern, TTL, cache invalidation, Redis

```
Features:
- GET /api/products — fetches from DB, caches in Redis (TTL: 5min)
- Second request returns from cache (with X-Cache: HIT header)
- POST /api/products — create product & invalidate cache
- PUT /api/products/:id — update & invalidate specific cache
- Cache stampede prevention (mutex lock on cache miss)
- Cache stats endpoint: hits, misses, hit ratio
```

---

#### 10. Server-Sent Events (SSE) — Live Notifications

**Concepts:** SSE vs WebSocket, EventSource, real-time one-way streams

```
Features:
- GET /api/notifications/stream — SSE endpoint (text/event-stream)
- POST /api/notifications — create notification (triggers SSE push)
- Client receives real-time updates without polling
- Auto-reconnect handling (Last-Event-ID header)
- Multiple event types: 'message', 'alert', 'update'
- Compare: when to use SSE vs WebSocket vs Long Polling
```

#### 11. API Gateway (Express)

**Concepts:** Reverse proxy, request forwarding, middleware chain

```
Features:
- Forward requests to different backend services based on path
  - /api/users/* → User Service (port 3001)
  - /api/products/* → Product Service (port 3002)
- Attach auth middleware before forwarding
- Rate limiting at gateway level
- Request/response logging
- Circuit breaker for downstream failures
- API key validation for third-party access
```
