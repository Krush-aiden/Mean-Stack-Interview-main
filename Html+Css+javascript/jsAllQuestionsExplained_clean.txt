### 1. What are the different data types in JavaScript?

JavaScript has two categories of data types:

**Primitive Types (7):**
- String    → "hello", 'world'
- Number    → 42, 3.14, NaN, Infinity
- BigInt    → 9007199254740991n
- Boolean   → true, false
- Undefined → variable declared but not assigned
- Null      → intentional absence of value
- Symbol    → Symbol('unique')

**Reference Types (Non-Primitive):**
- Object    → { key: 'value' }
- Array     → [1, 2, 3]
- Function  → function() {}
- Date      → new Date()
- RegExp    → /pattern/
- Map, Set, WeakMap, WeakSet

Key Difference:
- Primitives are stored in the **stack** (stored by value).
- Reference types are stored in the **heap** (stored by reference — the variable holds a pointer).

    typeof "hello"      // "string"
    typeof 42           // "number"
    typeof true         // "boolean"
    typeof undefined    // "undefined"
    typeof null         // "object"  ← historical bug in JS
    typeof Symbol()     // "symbol"
    typeof 10n          // "bigint"
    typeof {}           // "object"
    typeof []           // "object"  ← arrays are objects
    typeof function(){} // "function"

### 2. What is Hoisting in JavaScript?

Hoisting is JavaScript's default behavior of moving declarations to the top of their scope before code execution.

**var** → Hoisted and initialized with `undefined`
**let/const** → Hoisted but NOT initialized (Temporal Dead Zone)
**Function declarations** → Fully hoisted (can be called before declaration)
**Function expressions** → NOT hoisted

    console.log(a);   // undefined (var is hoisted)
    var a = 10;

    console.log(b);   // ReferenceError: Cannot access 'b' before initialization
    let b = 20;

    greet();           // "Hello!" (function declaration is hoisted)
    function greet() { console.log("Hello!"); }

    sayHi();           // TypeError: sayHi is not a function
    var sayHi = function() { console.log("Hi!"); };

### 3. What is the difference between == and === ?

**== (Loose Equality):** Compares values after type coercion.
**=== (Strict Equality):** Compares both value AND type without coercion.

    JavaScript == and ===: Tricky Examples

1. 5 == "5"
   Result: true
   Why: == converts the string "5" to the number 5 before comparing.

2. 5 === "5"
   Result: false
   Why: === requires both the value and type to match. One is a number; the other is a string.

3. false == 0
   Result: true
   Why: With ==, false is converted to 0.

4. "" == 0
   Result: true
   Why: With ==, the empty string is converted to the number 0.

5. null == undefined
   Result: true
   Why: This is a special rule for ==. null and undefined compare equal to each other without being converted.

6. null === undefined
   Result: false
   Why: They are different values and have different types.

7. null == 0
   Result: false
   Why: null only loosely equals undefined (and itself); it does not loosely equal 0.

8. [] == 0
   Result: true
   Why: The empty array converts to an empty string, and the empty string converts to 0.

9. [] == ""
   Result: true
   Why: When compared with a primitive using ==, the empty array converts to an empty string.

10. [] == ![]
    Result: true
    Why: Arrays are truthy, so ![] is false. The empty array converts to an empty string; then "" == false compares as 0 == 0.

11. NaN == NaN
    Result: false
    Why: NaN is not equal to any value, including itself. Use Number.isNaN(value) to check for NaN.

12. [] === []
    Result: false
    Why: Each [] creates a new array object. The two arrays are different objects.

13. const a = [];
    a === a
    Result: true
    Why: Both sides refer to the same array object.

Rule of thumb:
Use === by default. It avoids most surprising type conversions. Use == only when you specifically want its conversion rules.

### 5. What is the Temporal Dead Zone (TDZ)?

The Temporal Dead Zone is the period between the start of a block scope and the point where a `let` or `const` variable is declared. Accessing the variable during this period throws a ReferenceError.

    {
        // TDZ starts here for 'x'
        console.log(x);  // ReferenceError: Cannot access 'x' before initialization
        let x = 10;      // TDZ ends here
        console.log(x);  // 10
    }

Why TDZ exists: It catches bugs where variables are used before being properly initialized, unlike `var` which silently returns `undefined`.

### 6. What is Type Coercion in JavaScript?

Type coercion is the automatic or implicit conversion of values from one type to another.

**Implicit Coercion (automatic):**

    // String concatenation wins with +
    "5" + 3        // "53"  (number → string)
    "5" + true     // "5true"

    // Math operators convert to numbers
    "5" - 3        // 2     (string → number)
    "5" * 2        // 10
    "5" / 2        // 2.5
    true + 1       // 2     (true → 1)
    false + 1      // 1     (false → 0)
    null + 1       // 1     (null → 0)
    undefined + 1  // NaN   (undefined → NaN)

**Explicit Coercion (manual):**

    Number("42")     // 42
    String(42)       // "42"
    Boolean(0)       // false
    Boolean("")      // false
    Boolean("hello") // true
    parseInt("42px") // 42
    +"42"            // 42 (unary plus)

### Why does `[] + {}` evaluate to `"[object Object]"` while `{} + []` evaluates to `0` in a statement context?

**Explanation:**
This behavior involves two core JavaScript mechanisms: **Type Coercion (`ToPrimitive`)** and **Grammar/Parsing Context**.

1. **How `[]` and `{}` convert to strings:**
   - Both `[]` and `{}` are objects, but they use different `.toString()` implementations via the prototype chain.
   - `Array.prototype.toString()` overrides the default method and joins elements with commas. An empty array `[].toString()` converts to `""`.
   - `{}` inherits from `Object.prototype.toString()`, which returns a type identification tag `"[object Object]"`.

2. **Parsing Rules (Expression vs. Statement Context):**
   - **`[] + {}` (Expression Context):**
     Starts with `[]`, so the engine parses the whole line as an expression. Both operands are converted to primitive strings and concatenated:
     `"" + "[object Object]"` → `"[object Object]"`

   - **`{} + []` as a standalone statement (Statement Context):**
     When `{}` appears at the very beginning of a line without surrounding parentheses or assignment, the parser interprets `{}` as an **empty code block** (and ignores it). What remains is `+[]`, where `+` acts as a unary plus operator converting `[]` to a number:
     `+[]` → `+""` → `Number("")` → `0`

   - **`({} + [])` or `console.log({} + [])` (Expression Context):**
     Parentheses or function arguments force `{}` to be evaluated as an Object Literal instead of a code block, performing string concatenation:
     `"[object Object]" + ""` → `"[object Object]"`

```javascript
// Examples:
console.log([] + {});   // "[object Object]"
console.log({} + []);   // "[object Object]" (inside console.log, {} is an expression)

// Standalone execution in DevTools Console / REPL:
{} + []                 // 0 ({} is treated as an empty block, evaluates +[])
(({} + []))             // "[object Object]" (parentheses force expression context)

### 7. What is Static Typing vs Dynamic Typing?

**Static Typing (e.g., TypeScript, Java):**
- Variable types are declared at compile time.
- Type errors are caught before runtime.

    // TypeScript
    let name: string = "Krushna";
    name = 42; // ❌ Compile-time error

**Dynamic Typing (e.g., JavaScript, Python):**
- Variable types are determined at runtime.
- A variable can hold any type and can change type.

    let value = "hello";  // string
    value = 42;           // now a number — no error
    value = true;         // now a boolean — still no error

### 8. What is NaN in JavaScript?

NaN stands for "Not a Number." It indicates a value that is not a valid number, even though its type is `number`.

    typeof NaN         // "number"
    NaN === NaN        // false (NaN is never equal to itself)
    NaN == NaN         // false
    isNaN("hello")     // true (tries to convert, fails)
    Number.isNaN("hello")  // false (strict check — no conversion)
    Number.isNaN(NaN)      // true

    0 / 0              // NaN
    parseInt("abc")    // NaN
    Math.sqrt(-1)      // NaN
    undefined + 1      // NaN

Best Practice: Use `Number.isNaN()` instead of the global `isNaN()` for accurate checks.

### 77. What is `NaN` in JavaScript, and why do operations like `0 / 0`, `parseInt("abc")`, and `Math.sqrt(-1)` return `NaN`?

**Explanation:**
`NaN` stands for **"Not a Number"** (even though its data type is `'number'`). It represents an unrepresentable or mathematically invalid numeric result. Instead of throwing a fatal runtime error and crashing the program, JavaScript returns `NaN`.

**Step-by-Step Breakdown:**

1. **`0 / 0` → `NaN` (Indeterminate Arithmetic):**
   - Dividing a non-zero number by zero yields `Infinity` (e.g., `5 / 0` → `Infinity`).
   - Dividing `0` by `0` is mathematically indeterminate (undefined). Because there is no finite or infinite numeric boundary, JS evaluates it as `NaN`.

2. **`parseInt("abc")` → `NaN` (Failed String Parsing):**
   - `parseInt()` parses strings left-to-right to extract leading valid digits.
   - It fails at the very first character `'a'` (not a valid base-10 digit), so it gives up and returns `NaN`.
   - *Contrast:* `parseInt("123abc")` parses the leading valid digits and returns `123`.

3. **`Math.sqrt(-1)` → `NaN` (Outside Real Number Domain):**
   - The square root of a negative number requires complex/imaginary numbers ($i$).
   - The JS `Math` object only operates on standard **Real Numbers**, so taking the square root of a negative number returns `NaN`.

```javascript
// Examples:
typeof NaN;             // "number"

// 1. Indeterminate math
5 / 0;                  // Infinity
0 / 0;                  // NaN

// 2. Failed parsing
parseInt("123abc");     // 123
parseInt("abc");        // NaN

// 3. Imaginary number
Math.sqrt(16);          // 4
Math.sqrt(-1);          // NaN

### 10. What is Strict Mode in JavaScript?

Strict mode is a way to opt in to a restricted variant of JavaScript. It eliminates some silent errors, fixes mistakes that make it difficult for engines to optimize, and prohibits some syntax.

Enable with: `"use strict";` at the top of a file or function.

    "use strict";

    x = 10;              // ❌ ReferenceError (must declare variables)
    delete Object.prototype; // ❌ TypeError
    function f(a, a) {}  // ❌ SyntaxError (duplicate params)
    var obj = { a: 1, a: 2 }; // ❌ SyntaxError in strict mode

    "use strict";

    let x = 10;
    function myFunc() {}

    // ❌ SyntaxError: Delete of an unqualified identifier in strict mode
    delete x;        
    delete myFunc;

Key Restrictions:
- Cannot use undeclared variables.
- Cannot delete variables, functions, or undeletable properties.
- Cannot have duplicate parameter names.
- `this` in a regular function is `undefined` (not `window`).
- Octal literals (0123) are not allowed.
- `eval` and `arguments` cannot be reassigned.

### 11. Explain Scope and Scope Chain in JavaScript.

**Scope** determines the accessibility of variables, functions, and objects in your code.

**Types of Scope:**
1. **Global Scope** — Variables declared outside any function/block.
2. **Function Scope** — Variables declared inside a function (var, let, const).
3. **Block Scope** — Variables declared inside {} with let/const.
4. **Module Scope** — Variables declared in an ES module file.

**Scope Chain:**
When a variable is referenced, JS looks for it in the current scope first. If not found, it moves up to the parent scope, then grandparent, and so on until it reaches the global scope. This is the scope chain.

    let globalVar = "global";

    function outer() {
        let outerVar = "outer";

        function inner() {
            let innerVar = "inner";
            console.log(innerVar);   // "inner"  (own scope)
            console.log(outerVar);   // "outer"  (parent scope)
            console.log(globalVar);  // "global" (global scope — end of chain)
        }

        inner();
        // console.log(innerVar);  // ❌ ReferenceError
    }

    outer();

### 12. What is Pass by Value vs Pass by Reference?

**Pass by Value (Primitives):**
A copy of the value is passed. Changes to the copy don't affect the original.

    let a = 10;
    let b = a;     // b gets a COPY of a
    b = 20;
    console.log(a); // 10 (unchanged)

**Pass by Reference (Objects/Arrays):**

A reference (memory address) is passed. Changes through the reference affect the original.
---
#### 1. Mutating (Modifying the contents inside the same address)

Whether it's an Object or an Array, modifying the interior affects **all** variables pointing to it:
```javascript
// --- MUTATING AN OBJECT ---
let obj1 = { name: "Krushna" };
let obj2 = obj1;
obj2.name = "Alex";           // Modifies property inside address 0x123
console.log(obj1.name);       // "Alex" (Both changed!)

// --- MUTATING AN ARRAY ---
let arr1 = [1, 2, 3];
let arr2 = arr1;
arr2.push(99);                // Modifies contents inside address 0x456
console.log(arr1);            // [1, 2, 3, 99] (Both changed!)
```
#### 2. Reassigning (Pointing the variable to a brand-new address)

Whether it's an Object or an Array, assigning a brand-new value using `=` breaks the link and affects **only** that single variable:

```javascript
// --- REASSIGNING AN ARRAY ---
let arr1 = [1, 2, 3];
let arr2 = arr1;
arr2 = [4, 5, 6];             // Reassigns arr2 to a NEW address 0x789
console.log(arr1);            // [1, 2, 3] (Original unchanged!)

// --- REASSIGNING AN OBJECT ---
let obj1 = { name: "Krushna" };
let obj2 = obj1;
obj2 = { name: "Alex" };      // Reassigns obj2 to a NEW address 0x999
console.log(obj1.name);       // "Krushna" (Original unchanged!)
```

### 13. What is the Debugger statement?

The `debugger` statement acts as a breakpoint in your code. When a browser's developer tools are open, execution pauses at the `debugger` statement, allowing you to inspect variables, the call stack, and step through code.

    function calculate(a, b) {
        debugger;  // Execution pauses here when DevTools are open
        let sum = a + b;
        return sum;
    }

If DevTools are not open, the `debugger` statement has no effect.

### 14. What are Arrow Functions and how are they different from regular functions?

Arrow functions (=>) provide a concise syntax and have key differences from regular functions:

| Feature               | Regular Function        | Arrow Function          |
|---------------------- |------------------------ |------------------------ |
| Syntax                | function() {}           | () => {}                |
| `this` binding        | Own `this` (dynamic)    | Inherits parent `this`  |
| `arguments` object    | Yes                     | No                      |
| Can be constructor    | Yes                     | No                      |
| Hoisting              | Yes (declaration)       | No (expression only)    |

    --- `this` binding ---
        const obj = {
        name: "Krushna",

    // Regular Function: 'this' depends on caller (obj)
    regularFunc: function() {
        console.log("Regular:", this.name);
    },

    // Arrow Function: 'this' inherits from outer scope (window/global)
        arrowFunc: () => {
        console.log("Arrow:", this.name);
    }
    };

    obj.regularFunc(); // 👉 Regular: Krushna ('this' is obj)
    obj.arrowFunc();   // 👉 Arrow: undefined   ('this' inherited from outer scope)

        --- arguments` object ---
        // Regular Function
    function showArgs() {
    console.log(arguments[0], arguments[1]); // 👉 10, 20
    }
    showArgs(10, 20);

    // Arrow Function
    const showArgsArrow = () => {
    // console.log(arguments); // ❌ Uncaught ReferenceError: arguments is not defined
    };

    // Modern solution for Arrow Functions: Use Rest Parameters (...args)
    const showArgsModern = (...args) => {
    console.log(args[0], args[1]); // 👉 10, 20
    };
    showArgsModern(10, 20);

        --- Constructor ---
        // Regular Function as Constructor
    function Person(name) {
    this.name = name;
    }
    const p1 = new Person("Alex"); // 👉 Person { name: 'Alex' }

    // Arrow Function
    const User = (name) => {
    this.name = name;
    };
    // const u1 = new User("Alex"); // ❌ Uncaught TypeError: User is not a constructor

    --- Hosting Behavior ---
    // Regular Function Declaration: Works fine due to full hoisting
    greet(); // 👉 "Hello!"
    function greet() {
    console.log("Hello!");
    }

    // Arrow Function Expression: Fails due to TDZ
    // sayHi(); // ❌ Uncaught ReferenceError: Cannot access 'sayHi' before initialization
    const sayHi = () => {
    console.log("Hi!");
    };

### 15. What is an IIFE (Immediately Invoked Function Expression)?

An IIFE is a function that runs as soon as it is defined. It creates a private scope, preventing variable pollution of the global scope.

    (function() {
        var x = 10;
        console.log(x);  // 10
    })();
    // console.log(x);  // ❌ ReferenceError — x is not accessible

    // With arrow function
    (() => {
        const msg = "IIFE with arrow";
        console.log(msg);
    })();

    // With parameters
    (function(name) {
        console.log("Hello, " + name);
    })("Krushna");

Use Cases:
- Avoid polluting global scope.
- Module pattern (before ES modules).
- Initialization code that runs once.

### 16. What are Higher-Order Functions?

A higher-order function is a function that either:
1. Takes one or more functions as arguments, OR
2. Returns a function as its result.

    // Takes a function as argument
    function add(x, y) {
        return x + y;
    }

    // 2. Define the operator function that receives a callback
    function operate(a, b, callback) {
        // 'callback' is literally the 'add' function we pass in!
        return callback(a, b); 
    }

    // 3. Pass 'add' (WITHOUT parentheses ()) as the 3rd argument
    const result = operate(5, 4, add);

    console.log(result); // 👉 Output: 9

    // Returns a function
    function multiplier(factor) {
        return function gstcalc(num) {
            return num * factor;
        };
    }
    const double = multiplier(2);
    console.log(double(5));  // 10

Built-in Higher-Order Functions:
- Array.map(), Array.filter(), Array.reduce()
- Array.forEach(), Array.sort(), Array.find()
- setTimeout(), setInterval(), addEventListener()

### 17. What are Callbacks?

A callback is a function passed as an argument to another function, which is then invoked inside the outer function.

    // Synchronous callback

    function sum(a, b) {
        console.log("2. Inside sum function: Calculating " + a + " + " + b); // 📍 Inside sum!
        return a + b;
    }

    // 2. Define processUser
    function processUser(name, operation) {
        console.log("1. Inside processUser: Starting process for " + name); // 📍 Inside processUser

        // 👈 JS pauses processUser here and jumps into sum(5, 4)!
        const result = operation(5, 4); 

        // 👈 JS returns back to processUser with result = 9
        console.log("3. Inside processUser: The sum result is " + result);   // 📍 Inside processUser
    }

    // 3. Execute
    processUser("Krushna", sum);

    // Asynchronous callback

    function displayWeatherReport(city, temperature) {
        console.log("3. Callback Executed! " + city + " temperature is " + temperature + "°C.");
    }

    // 2. Higher-Order Async Function (Simulates fetching data from a server)
    function getWeather(city, callback) {
        console.log("1. Requesting weather data for " + city + " from server...");

        // Simulate 2-second network delay
        setTimeout(function() {
            // Data arrives from server 2 seconds later!
            const temp = 28; 

            console.log("2. Server response received!");

            // Trigger the callback function, passing the fetched temperature
            callback(city, temp);
        }, 2000);

        console.log("1b. Waiting for server response... (UI stays responsive!)");
    }

// 3. Execution (Pass 'displayWeatherReport' as the callback)
getWeather("Bhubaneswar", displayWeatherReport);

### 18. What is Callback Hell and how to avoid it?

Callback Hell is when multiple nested callbacks create deeply indented, hard-to-read code (also called "Pyramid of Doom").

    // ❌ CALLBACK HELL (Deeply nested, hard to read, nightmare error handling)
    function getUser(callback) {
        setTimeout(() => {
            console.log("1. User found!");
            callback(null, { id: 101, name: "Krushna" }); // null means 'no error'
        }, 1000);
    }

    function getOrders(userId, callback) {
        setTimeout(() => {
            console.log("2. Orders found for User ID: " + userId);
            callback(null, ["Laptop", "Mouse"]);
        }, 1000);
    }

    function calculateTotal(ordersArray, callback) {
        setTimeout(() => {
            console.log("3. Calculated total for " + ordersArray.length + " items.");
            callback(null, "$1500");
        }, 1000);
    }


    // --- 2. THE CALLBACK HELL (The Execution) ---

    console.log("Starting process...");

    getUser(function(err, user) {
        if (err) return console.log(err);

        // Now we have the user, let's get their orders
        getOrders(user.id, function(err, orders) {
            if (err) return console.log(err);

            // Now we have the orders, let's calculate the total
            calculateTotal(orders, function(err, totalAmount) {
                if (err) return console.log(err);

                // Finally, we have everything!
                console.log(`\n🎉 SUCCESS: ${user.name} bought items worth ${totalAmount}`);
            });
        });
    });

    // ✅ MODERN SOLUTION (Clean, flat, single try/catch block)
    // --- 1. Promise-based Async Functions ---
    function getUser() {
        return new Promise((resolve) => {
            setTimeout(() => {
                console.log("1. User found!");
                resolve({ id: 101, name: "Krushna" }); // Send data out via resolve
            }, 1000);
        });
    }

    function getOrders(userId) {
        return new Promise((resolve) => {
            setTimeout(() => {
                console.log("2. Orders found for User ID: " + userId);
                resolve(["Laptop", "Mouse"]);
            }, 1000);
        });
    }

    function calculateTotal(ordersArray) {
        return new Promise((resolve) => {
            setTimeout(() => {
                console.log("3. Calculated total for " + ordersArray.length + " items.");
                resolve("$1500");
            }, 1000);
        });
    }

    async function processOrder() {
        console.log("Starting process...");

        try {
            const user = await getUser();
            const orders = await getOrders(user.id);
            const totalAmount = await calculateTotal(orders);

            console.log(`\n🎉 SUCCESS: ${user.name} bought items worth ${totalAmount}`);
        } catch (err) {
            console.error("An error occurred:", err);
        }
    }

    processOrder();

    // Call it cleanly:
    completeCheckout("user_101");

    // --- 2. PROMISE CHAINING SOLUTION ---
    console.log("Starting process...");

    let userData; // Variable to keep track of user info across .then() blocks

    getUser()
        .then((user) => {
            userData = user;
            return getOrders(user.id); // Return next Promise
        })
        .then((orders) => {
            return calculateTotal(orders); // Return next Promise
        })
        .then((totalAmount) => {
            console.log(`\n🎉 SUCCESS: ${userData.name} bought items worth ${totalAmount}`);
        })
        .catch((err) => {
            console.error("An error occurred:", err);
        });

    **Solutions:**
    1. **Promises** — chain .then() instead of nesting.
    2. **Async/Await** — write async code that looks synchronous.
    3. **Named functions** — extract each callback into a named function.
    4. **Modularization** — break code into smaller modules.

// Production Example: Private Cache Manager

function createApiCache() {
    // Private state inside closure — impossible to mutate from outside
    const cache = new Map(); 

    return {
        async get(key, fetcherFn) {

        // 🔍 CLOSURE LOOKUP:
        // When get() runs, JS looks inside its internal [[Scopes]] backpack.
        // It finds 'cache' in the closed-over scope of createApiCache!

        if (cache.has(key)) {
            return cache.get(key);
        }
        
        const data = await fetcherFn();
        cache.set(key, data); // 👈 Directly mutates the closed-over Map
        return data;
        }
        
        clear() {
            cache.clear();
        }
    };
}

1. CORE DEFINITION (30-SECOND VERBAL PITCH)
--------------------------------------------------------------------------------
"Memoization is a specific optimization technique that speeds up programs by 
caching the results of expensive function calls and returning the cached result 
when the exact same inputs/arguments occur again."


--------------------------------------------------------------------------------
2. REAL-WORLD PRODUCTION EXAMPLE: GENERIC MEMOIZE UTILITY (POLYFILL)

// Production-grade Memoize Wrapper using Map and Custom Resolver
function memoize(fn, resolver) {
    const cache = new Map();

    return function(...args) {
        // Allow custom cache key generation (defaults to JSON stringification)
        const key = resolver ? resolver(...args) : JSON.stringify(args);

        if (cache.has(key)) {
            console.log(`[Cache Hit] returning cached result for key: "${key}"`);
            return cache.get(key);
        }

        console.log(`[Cache Miss] calculating fresh result for key: "${key}"`);
        const result = fn.apply(this, args);
        cache.set(key, result);
        return result;
    };
}

3. SIMPLE ARITHMETIC EXAMPLES (MULTIPLICATION & FACTORIAL)
--------------------------------------------------------------------------------
const expensiveCalculation = (n) => {
    let sum = 0;
    for (let i = 0; i < n; i++) sum += i;
    return sum;
};

const memoizedCalc = memoize(expensiveCalculation);
memoizedCalc(100000000); // [Cache Miss] calculating fresh result...
memoizedCalc(100000000); // [Cache Hit] returning cached result...

// Example 2: Recursive Multiplication / Factorial
const memoizedFactorial = memoize(function(n) {
    if (n <= 1) return 1;
    return n * memoizedFactorial(n - 1);
});

console.log(memoizedFactorial(5));  // Calculates: 5 * 4 * 3 * 2 * 1 = 120
console.log(memoizedFactorial(5));  // Returns 120 instantly from cache!

### 23. What is Currying in JavaScript?

Currying is a functional programming technique that transforms a function with multiple arguments into a sequence of nesting functions, each taking a single argument: f(a, b, c) → f(a)(b)(c).

    // Normal function
    function add(a, b, c) {
        return a + b + c;
    }
    add(1, 2, 3);  // 6

    // Curried version (Regular Functions)
    function curriedAdd(a) {
        return function(b) {
            return function(c) {
                return a + b + c;
            };
        };
    }
    curriedAdd(1)(2)(3);  // 6

    // Arrow function version
    const curriedAdd2 = a => b => c => a + b + c;


**Real-World Use Cases:**
1. Function Factories (e.g., const logError = log("ERROR"))
2. Reusable Event Handlers / Middleware (e.g., const handleInput = field => event => ...)
3. Modularity in Functional Programming pipelines


**Currying vs. Partial Application:**
- Currying always converts a function into single-argument functions: f(a)(b)(c)
- Partial application fixes some arguments now and accepts the remaining arguments later: f(a)(b, c) or f(a, b)(c)


**Output-Tracing / Coding Interview Variations:**

Variation 1: Infinite Currying — add(1)(2)(3)...()
    function add(a) {
        return function(b) {
            if (b !== undefined) {
                return add(a + b);  // Recursive step
            }
            return a;  // Terminating condition when called with no args ()
        };
    }

    add(1)(2)(3)();      // 6
    add(5)(10)(15)(2)(); // 32

### 24. What is Function Composition?

Function composition is the process of combining two or more functions to produce a new function. The output of one function becomes the input of the next.

    function double(x) {
    return x * 2;
    }

    function increment(x) {
    return x + 1;
    }

    function square(x) {
    return x * x;
    }

    // Manual composition :
    const result = square(increment(double(3)));  // square(increment(6)) → square(7) → 49

    // Compose utility (right to left) :
    function compose(...fns) {
    return function(initialValue) {
        // reduceRight iterates through the array from last to first
        return fns.reduceRight(function(accumulator, currentFunction) {
        return currentFunction(accumulator);
        }, initialValue);
    };
    }

    const transform = compose(square, increment, double);
    transform(3); // 49

    // Pipe utility (left to right — more readable) :
    function pipe(...fns) {
    return function(initialValue) {
        // reduce iterates through the array from first to last
        return fns.reduce(function(accumulator, currentFunction) {
        return currentFunction(accumulator);
        }, initialValue);
    };
    }

    const transform2 = pipe(double, increment, square);
    transform2(3); // 49

### 26. What is call(), apply(), and bind()?

These methods explicitly set the value of `this` when calling a function.

    **call()** — call() is a built-in Function.prototype method that immediately invokes a function, explicitly passing a specified object to be used as this inside the function, passes arguments individually

    function greet(greeting, punctuation) {
        console.log(`${greeting}, ${this.name}${punctuation}`);
    }
    const user = { name: "Krushna" };
    greet.call(user, "Hello", "!");  // "Hello, Krushna!"

    **apply()** — same as call(), but passes arguments as an array.

    greet.apply(user, ["Hi", "."]);  // "Hi, Krushna."

    // Classic Use Case: Unpacking arrays for built-in functions
    const nums = [10, 5, 20];
    Math.max.apply(null, nums);  // 20

    **bind()** — it returns a brand new function with its `this` keyword permanently locked to the provided object. Does NOT invoke immediately.

    const boundGreet = greet.bind(user, "Hey");
    boundGreet("!!");  // "Hey, Krushna!!"

    // 2nd example :
    function showName() {
        console.log(this.name);
    }

    const user1 = { name: "Krushna" };
    const user2 = { name: "Rahul" };

    const bound1 = showName.bind(user1);
    const bound2 = bound1.bind(user2); // Re-binding bound1 to user2

    bound2(); // What gets logged?

    // Useful for event handlers
    const button = { label: "Submit" };
    const handleClick = function() { console.log(this.label); };
    document.addEventListener("click", handleClick.bind(button));

    Key Difference Summary:
    - call  → invoke now, args separately
    - apply → invoke now, args as array
    - bind  → don't invoke, return new function

### 28. What are Object Prototypes?

Every JavaScript object has a hidden internal property [[Prototype]] that links to another object called its prototype. This forms a **prototype chain**.

    const arr = [1, 2, 3];

    Object.getPrototypeOf(arr) === Array.prototype;  // true

    function Animal(name) { this.name = name; }

    // Prototype chain lookup
    // dog → Animal.prototype → Object.prototype → null

### 30. What is the Rest Parameter and Spread Operator?

### 31. What is Optional Chaining (?.) in JavaScript?

### 32. What is the Nullish Coalescing Operator (??)?

The `??` operator returns the right-hand operand when the left-hand operand is `null` or `undefined`. Unlike `||`, it does NOT treat `0`, `""`, or `false` as falsy.

    null ?? "default"      // "default"
    undefined ?? "default" // "default"
    0 ?? "default"         // 0        ← differs from ||
    "" ?? "default"        // ""       ← differs from ||
    false ?? "default"     // false    ← differs from ||

    // Comparison with ||
    0 || "default"         // "default" (0 is falsy)
    0 ?? "default"         // 0         (0 is not null/undefined)

    // Logical assignment operators (ES2021)
    let a = null;
    a ??= "hello";   // a = "hello" (assigns only if null/undefined)
    a ||= "world";   // logical OR assignment
    a &&= "done";    // logical AND assignment

### 33. What is Synchronous vs Asynchronous JavaScript?

**Synchronous:** Code executes line by line, blocking execution until each operation completes.

    console.log("1");
    console.log("2");  // Waits for line 1 to complete
    console.log("3");  // Output: 1, 2, 3

**Asynchronous:** Code can initiate operations that complete later, allowing other code to run in the meantime (non-blocking).

    console.log("Start");
    setTimeout(() => console.log("Timeout"), 0);
    console.log("End");
    // Output: Start, End, Timeout

Async mechanisms: setTimeout, setInterval, Promises, async/await, fetch, event listeners, I/O operations.

### 34. What are Promises in JavaScript?

A Promise is an object representing the eventual completion or failure of an asynchronous operation.

**Three States:**
1. **Pending** — initial state, neither fulfilled nor rejected
2. **Fulfilled** — operation completed successfully
3. **Rejected** — operation failed

    const myPromise = new Promise((resolve, reject) => {
        const success = true;
        if (success) {
            resolve("Data received!");
        } else {
            reject("Error occurred!");
        }
    });

    myPromise
        .then(result => console.log(result))    // "Data received!"
        .catch(error => console.log(error))
        .finally(() => console.log("Done"));    // Always runs

**Promise chaining:**

    fetch("/api/user")
        .then(response => response.json())
        .then(user => fetch(`/api/posts/${user.id}`))
        .then(response => response.json())
        .then(posts => console.log(posts))
        .catch(error => console.error(error));

### 35. What are Promise.all, Promise.allSettled, Promise.race, and Promise.any?

    const p1 = Promise.resolve(1);
    const p2 = Promise.resolve(2);
    const p3 = Promise.reject("Error");

**Promise.all()** — Waits for ALL to fulfill. Rejects if ANY rejects.

    Promise.all([p1, p2]).then(console.log);     // [1, 2]
    Promise.all([p1, p3]).catch(console.log);    // "Error"

**Promise.allSettled()** — Waits for ALL to settle (fulfill or reject).

    Promise.allSettled([p1, p3]).then(console.log);
    // [{ status: "fulfilled", value: 1 }, { status: "rejected", reason: "Error" }]

**Promise.race()** — Returns the FIRST promise to settle (fulfill or reject).

    Promise.race([p1, p2]).then(console.log);    // 1 (whichever resolves first)

**Promise.any()** — Returns the FIRST fulfilled promise. Ignores rejections unless all reject.

    Promise.any([p3, p1]).then(console.log);     // 1 (first success)

### 36. What is Async/Await?

Async/Await is syntactic sugar over Promises. It makes asynchronous code look and behave like synchronous code.

    // Promise-based
    function getData() {
        return fetch("/api/data")
            .then(res => res.json())
            .then(data => console.log(data))
            .catch(err => console.error(err));
    }

    // Async/Await version
    async function getData() {
        try {
            const res = await fetch("/api/data");
            const data = await res.json();
            console.log(data);
        } catch (err) {
            console.error(err);
        }
    }

Key Points:
- `async` function always returns a Promise.
- `await` pauses execution until the Promise resolves.
- Use `try/catch` for error handling.
- `await` can only be used inside an `async` function (or at top-level in modules).

### 37. Explain the Event Loop in JavaScript.

JavaScript is single-threaded but handles asynchronous operations using the Event Loop.

**Components:**
1. **Call Stack** — Executes synchronous code (LIFO).
2. **Web APIs** — Browser handles setTimeout, fetch, DOM events, etc.
3. **Microtask Queue** — Promises (.then), queueMicrotask, MutationObserver.
4. **Macrotask Queue (Task Queue)** — setTimeout, setInterval, setImmediate, I/O.

**Execution Order:**
1. Execute all synchronous code (call stack).
2. Drain the microtask queue completely.
3. Execute ONE macrotask.
4. Repeat from step 2.

    console.log("1");                           // Sync

    setTimeout(() => console.log("2"), 0);      // Macrotask

    Promise.resolve().then(() => {
        console.log("3");                       // Microtask
    });

    queueMicrotask(() => console.log("4"));     // Microtask

    console.log("5");                           // Sync

    // Output: 1, 5, 3, 4, 2

**Key Insight:** Microtasks (Promises) ALWAYS execute before macrotasks (setTimeout), even if setTimeout has 0ms delay.

    console.log("Script start");
    setTimeout(() => console.log("setTimeout"), 0);
    Promise.resolve().then(() => console.log("Promise 1"))
                     .then(() => console.log("Promise 2"));
    console.log("Script end");
    // Output: Script start → Script end → Promise 1 → Promise 2 → setTimeout

### 38. What is the difference between Microtasks and Macrotasks?

| Microtasks                    | Macrotasks                        |
|------------------------------ |---------------------------------- |
| Promise.then/catch/finally    | setTimeout                        |
| queueMicrotask()              | setInterval                       |
| MutationObserver              | setImmediate (Node.js)            |
| process.nextTick (Node.js)    | I/O operations                    |
|                               | requestAnimationFrame             |
|                               | UI rendering                      |

Priority: Microtasks > Macrotasks.
After each macrotask, ALL microtasks are drained before the next macrotask runs.

### 39. What is the role of Deferred Scripts in JavaScript?

The `defer` and `async` attributes control how external scripts are loaded and executed.

**Normal <script>:** Blocks HTML parsing. Downloads and executes immediately.
**<script defer>:** Downloads in parallel, executes AFTER HTML is fully parsed. Maintains order.
**<script async>:** Downloads in parallel, executes AS SOON as downloaded. No guaranteed order.

    <!-- Blocks rendering -->
    <script src="app.js"></script>

    <!-- Non-blocking, executes after DOM is ready, in order -->
    <script defer src="app.js"></script>

    <!-- Non-blocking, executes ASAP, no order guarantee -->
    <script async src="analytics.js"></script>

Best Practice: Use `defer` for scripts that depend on DOM. Use `async` for independent scripts (analytics, ads).

### 40. Explain map(), filter(), reduce(), and forEach().

**map()** — Creates a new array by transforming each element. Returns new array.

    [1, 2, 3].map(x => x * 2);  // [2, 4, 6]

**filter()** — Creates a new array with elements that pass a test. Returns new array.

    [1, 2, 3, 4].filter(x => x > 2);  // [3, 4]

**reduce()** — Reduces array to a single value using an accumulator.

    [1, 2, 3, 4].reduce((acc, x) => acc + x, 0);  // 10

**forEach()** — Executes a function for each element. Returns undefined. Cannot break/return.

    [1, 2, 3].forEach(x => console.log(x));  // 1, 2, 3

Key Differences:
- map/filter/reduce return new arrays/values — forEach returns undefined.
- map/filter are pure (don't modify original) — forEach is for side effects.
- reduce is most flexible — can replicate map and filter behavior.

**Chaining:**

    const people = [
        { name: "Alice", age: 25 },
        { name: "Bob", age: 31 },
        { name: "Charlie", age: 35 }
    ];

    const totalAgeOver30 = people
        .filter(p => p.age > 30)
        .map(p => p.age)
        .reduce((sum, age) => sum + age, 0);
    // 66

### 41. What is the difference between find(), findIndex(), indexOf(), and includes()?

    const arr = [10, 20, 30, 40];

**find()** — Returns the FIRST element matching a condition (or undefined).

    arr.find(x => x > 25);      // 30

**findIndex()** — Returns the INDEX of the first match (or -1).

    arr.findIndex(x => x > 25); // 2

**indexOf()** — Returns the index of a specific value (strict equality).

    arr.indexOf(30);            // 2
    arr.indexOf(99);            // -1

**includes()** — Returns boolean — does the array contain this value?

    arr.includes(30);           // true
    arr.includes(99);           // false

Key: find/findIndex use a callback (flexible conditions). indexOf/includes compare exact values.

### 42. What is the difference between slice() and splice()?

**slice(start, end)** — Returns a shallow copy of a portion. Does NOT modify original.

    const arr = [1, 2, 3, 4, 5];
    arr.slice(1, 3);   // [2, 3]
    arr.slice(-2);     // [4, 5]
    console.log(arr);  // [1, 2, 3, 4, 5] (unchanged)

**splice(start, deleteCount, ...items)** — Adds/removes elements. MODIFIES original array.

    const arr2 = [1, 2, 3, 4, 5];
    arr2.splice(1, 2);          // removes [2, 3] → arr2 = [1, 4, 5]
    arr2.splice(1, 0, 10, 20);  // inserts at index 1 → arr2 = [1, 10, 20, 4, 5]

### 43. What is the difference between for...in and for...of?

**for...in** — Iterates over enumerable PROPERTY KEYS (including inherited). Use for objects.

    const obj = { a: 1, b: 2, c: 3 };
    for (let key in obj) {
        console.log(key);    // "a", "b", "c"
    }

**for...of** — Iterates over iterable VALUES. Use for arrays, strings, Maps, Sets.

    const arr = [10, 20, 30];
    for (let value of arr) {
        console.log(value);  // 10, 20, 30
    }

Warning: Don't use `for...in` on arrays — it iterates keys (indices as strings) and may include prototype properties.

### 49. What is the difference between Shallow Clone and Deep Clone?

**Shallow Clone** — Copies only the top-level properties. Nested objects are still referenced (shared).

    const original = { name: "Krushna", address: { city: "BBR" } };

    // Shallow clone methods
    const clone1 = Object.assign({}, original);
    const clone2 = { ...original };

    clone1.address.city = "Delhi";
    console.log(original.address.city);  // "Delhi" ← affected!

**Deep Clone** — Creates a completely independent copy, including all nested objects.

    // Method 1: JSON (simple but has limitations)
    const deep1 = JSON.parse(JSON.stringify(original));
    // ❌ Loses: functions, undefined, Date, RegExp, Map, Set, circular refs

    // Method 2: structuredClone() (ES2022 — recommended)
    const deep2 = structuredClone(original);
    // ✅ Handles: Date, RegExp, Map, Set, ArrayBuffer, circular refs
    // ❌ Does not clone: functions, DOM nodes, symbols

    // Method 3: Recursive function
    function deepClone(obj) {
        if (obj === null || typeof obj !== "object") return obj;
        const clone = Array.isArray(obj) ? [] : {};
        for (let key in obj) {
            if (obj.hasOwnProperty(key)) {
                clone[key] = deepClone(obj[key]);
            }
        }
        return clone;
    }

    // Method 4: Libraries
    // lodash: _.cloneDeep(obj)

### 50. What are ES6 Classes?

Classes are syntactic sugar over JavaScript's prototype-based inheritance.

    class Animal {
        constructor(name) {
            this.name = name;
        }

        speak() {
            return `${this.name} makes a sound`;
        }

        static create(name) {
            return new Animal(name);
        }
    }

    class Dog extends Animal {
        constructor(name, breed) {
            super(name);  // must call super() before using 'this'
            this.breed = breed;
        }

        speak() {
            return `${this.name} barks`;  // method overriding
        }
    }

    const dog = new Dog("Rex", "Labrador");
    dog.speak();        // "Rex barks"
    dog instanceof Dog;  // true
    dog instanceof Animal;  // true

### 53. What are Symbols in JavaScript?

### 54. What are Generators and Iterators?

**Iterator Protocol:** An object is iterable if it implements a `[Symbol.iterator]()` method that returns an object with a `next()` method.

    const iterable = {
        [Symbol.iterator]() {
            let i = 0;
            return {
                next() {
                    return i < 3
                        ? { value: i++, done: false }
                        : { done: true };
                }
            };
        }
    };

    for (const val of iterable) console.log(val);  // 0, 1, 2

**Generator Function (function*):** Creates an iterator more easily. Uses `yield` to pause/resume.

    function* numberGen() {
        yield 1;
        yield 2;
        yield 3;
    }

    const gen = numberGen();
    gen.next();  // { value: 1, done: false }
    gen.next();  // { value: 2, done: false }
    gen.next();  // { value: 3, done: false }
    gen.next();  // { value: undefined, done: true }

    // Infinite sequence
    function* infiniteCounter() {
        let i = 0;
        while (true) yield i++;
    }

    // With yield delegation
    function* delegated() {
        yield* [1, 2, 3];
        yield* "abc";
    }
    [...delegated()];  // [1, 2, 3, "a", "b", "c"]

Use Cases: Lazy evaluation, infinite sequences, async flow control, state machines.

### 56. What is Proxy and Reflect in JavaScript?

**Proxy** creates a wrapper around an object to intercept and customize operations (get, set, delete, etc.).

    const user = { name: "Krushna", age: 25 };

    const proxy = new Proxy(user, {
        get(target, prop) {
            console.log(`Reading ${prop}`);
            return prop in target ? target[prop] : "Property not found";
        },
        set(target, prop, value) {
            if (prop === "age" && typeof value !== "number") {
                throw new TypeError("Age must be a number");
            }
            target[prop] = value;
            return true;
        }
    });

    proxy.name;       // "Reading name" → "Krushna"
    proxy.unknown;    // "Reading unknown" → "Property not found"
    proxy.age = 30;   // ✅
    proxy.age = "30"; // ❌ TypeError

**Reflect** provides methods to perform default object operations (mirrors Proxy handler methods).

    Reflect.get(user, "name");         // "Krushna"
    Reflect.set(user, "age", 30);      // true
    Reflect.has(user, "name");         // true
    Reflect.deleteProperty(user, "age"); // true
    Reflect.ownKeys(user);            // ["name"]

Use Cases: Validation, logging, observable objects, reactive systems (Vue.js uses Proxy).

### 57. What is WeakRef and FinalizationRegistry?

**WeakRef** holds a weak reference to an object — it doesn't prevent garbage collection.

    let obj = { data: "important" };
    const weakRef = new WeakRef(obj);

    weakRef.deref();  // { data: "important" }
    obj = null;       // obj can be garbage collected
    weakRef.deref();  // undefined (after GC runs)

**FinalizationRegistry** lets you run cleanup code when an object is garbage collected.

    const registry = new FinalizationRegistry((heldValue) => {
        console.log(`${heldValue} was garbage collected`);
    });

    let obj = { name: "temp" };
    registry.register(obj, "my-object");
    obj = null;  // Eventually: "my-object was garbage collected"

Use Cases: Cache management, resource cleanup, memory-sensitive applications.
Warning: Don't rely on these for critical logic — GC timing is unpredictable.

### 59. What are the types of Errors in JavaScript?

1. **SyntaxError** — Invalid code syntax.
   console.log("hello"  // Missing closing parenthesis

2. **ReferenceError** — Accessing an undeclared variable.

### 63. What is the difference between Loosely Coupled and Tightly Coupled?

### 67. What are Top-Level Await and its use cases?

    // Conditional dependency
    const adapter = await (isProduction
        ? import("./prodAdapter.js")
        : import("./devAdapter.js"));

### 68. What is Debouncing and Throttling?

**Debouncing:** Delays function execution until after a specified wait time has passed since the last call. Resets timer on each new call.

    function debounce(fn, delay) {
        let timer;
        return function(...args) {
            clearTimeout(timer);
            timer = setTimeout(() => fn.apply(this, args), delay);
        };
    }

    // Usage: Search input (only fires after user stops typing)
    const handleSearch = debounce((query) => {
        fetch(`/api/search?q=${query}`);
    }, 300);

**Throttling:** Limits function execution to at most once per specified time interval.

    function throttle(fn, limit) {
        let inThrottle = false;
        return function(...args) {
            if (!inThrottle) {
                fn.apply(this, args);
                inThrottle = true;
                setTimeout(() => inThrottle = false, limit);
            }
        };
    }

    // Usage: Scroll handler (fire at most once per 200ms)
    window.addEventListener("scroll", throttle(handleScroll, 200));

Key Difference:
- Debounce: "Wait until done, then fire once." (search input, resize)
- Throttle: "Fire at regular intervals." (scroll, mouse move)

### 69. What is Event Loop in the context of setTimeout(fn, 0)?

Even with a 0ms delay, `setTimeout(fn, 0)` does NOT execute immediately. The callback is placed in the macrotask queue and only runs after:
1. The current call stack is empty.
2. All microtasks have been processed.

    console.log("A");
    setTimeout(() => console.log("B"), 0);
    Promise.resolve().then(() => console.log("C"));
    console.log("D");

    // Output: A → D → C → B
    // A, D: synchronous (call stack)
    // C: microtask (Promise) — runs before macrotask
    // B: macrotask (setTimeout) — runs last

### 70. What is the difference between Object.freeze(), Object.seal(), and Object.preventExtensions()?

**Object.freeze()** — No add, no delete, no modify.

    const obj = { name: "Krushna" };
    Object.freeze(obj);
    obj.name = "Alex";      // ❌ silently fails (or error in strict mode)
    obj.age = 25;           // ❌ can't add
    delete obj.name;        // ❌ can't delete

**Object.seal()** — No add, no delete, but CAN modify existing properties.

    const obj2 = { name: "Krushna" };
    Object.seal(obj2);
    obj2.name = "Alex";     // ✅ can modify
    obj2.age = 25;          // ❌ can't add
    delete obj2.name;       // ❌ can't delete

**Object.preventExtensions()** — No add, but CAN modify and delete.

    const obj3 = { name: "Krushna" };
    Object.preventExtensions(obj3);
    obj3.name = "Alex";     // ✅ can modify
    obj3.age = 25;          // ❌ can't add
    delete obj3.name;       // ✅ can delete

Note: All three are SHALLOW — nested objects are still mutable.

### 71. What is the Spread Operator in function calls vs Array/Object literals?

    // In function calls — spreads array as arguments
    function sum(a, b, c) { return a + b + c; }
    sum(...[1, 2, 3]);  // 6

    // In array literals — spreads into new array
    const merged = [...[1, 2], ...[3, 4]];  // [1, 2, 3, 4]

    // In object literals — spreads properties
    const merged2 = { ...{a: 1}, ...{b: 2} };  // {a: 1, b: 2}

    // Overriding properties (last wins)
    const updated = { ...user, name: "Alex" };

### 72. What is Short-Circuit Evaluation?

JavaScript's `&&` and `||` operators use short-circuit evaluation — they stop evaluating as soon as the result is determined.

    // OR (||) — returns first truthy value or last value
    false || "hello"     // "hello"
    "hi" || "hello"      // "hi"
    0 || "" || "default" // "default"

    // AND (&&) — returns first falsy value or last value
    true && "hello"      // "hello"
    false && "hello"     // false
    "hi" && 0 && "hello" // 0

    // Practical usage
    const name = user && user.name;         // safe access (before ?.)
    const value = input || "default";       // default value (before ??)
    isLoggedIn && showDashboard();          // conditional execution

### 73. What are WeakMap and WeakMap vs Map?

**WeakMap:** Keys must be objects, entries are weakly held (garbage collectible).

    let obj = { id: 1 };
    const wm = new WeakMap();
    wm.set(obj, "metadata");
    wm.get(obj);  // "metadata"
    obj = null;   // entry can be garbage collected

| Feature        | Map                        | WeakMap                   |
|--------------- |--------------------------- |-------------------------- |
| Keys           | Any type                   | Objects only              |
| GC             | Strong reference           | Weak reference            |
| Iterable       | Yes                        | No                        |
| Size           | .size property             | No                        |
| Methods        | get, set, has, delete, forEach | get, set, has, delete |

Use Cases: Storing private data, DOM node metadata, caching without memory leaks.

### 74. What is the globalThis object?

`globalThis` provides a standard way to access the global object across all JavaScript environments.

    // Browser:  globalThis === window
    // Node.js:  globalThis === global
    // Web Workers: globalThis === self

    globalThis.setTimeout(() => console.log("works everywhere"), 100);

Previously, accessing the global object required environment-specific checks:
    typeof window !== "undefined" ? window : typeof global !== "undefined" ? global : self;

### 75. What is the difference between Error Handling approaches in JavaScript?

**try/catch/finally:**

    try {
        const data = JSON.parse(invalidJSON);
    } catch (error) {
        console.error("Parse failed:", error.message);
    } finally {
        console.log("Always runs");
    }

**Promise .catch():**

    fetch("/api/data")
        .then(res => res.json())
        .catch(err => console.error(err));

**Async/Await with try/catch:**

    async function getData() {
        try {
            const res = await fetch("/api/data");
            return await res.json();
        } catch (err) {
            console.error(err);
        }
    }

**Global error handlers:**

    // Browser
    window.onerror = (msg, source, line, col, error) => {};
    window.addEventListener("unhandledrejection", (event) => {
        console.error("Unhandled promise rejection:", event.reason);
    });

    // Node.js
    process.on("uncaughtException", (err) => {});
    process.on("unhandledRejection", (reason) => {});
